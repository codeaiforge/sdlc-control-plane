## Design Decisions

- **One 422 for both unaccepted outcomes**, discriminated by `disposition` in the body. The seam returns 422 for a contract failure and a policy failure alike; splitting the statuses would have rewritten a seam 0.4 shipped as PASSED, at ~5 SP and Complex tier. The discriminator is made rigorous without `oneOf` by a checked two-sided relation: a body that satisfies `EvidenceRecord` and still 422s must be `needs-remediation` with `policy_id`; one that violates it must be `rejected` without.
- **`openapi.json`, not YAML.** `yaml` and `js-yaml` do not resolve in this workspace, so YAML meant the repo's first new dependency, a `pnpm-lock.yaml` change that raises this task's own emitted tier, and an ADR — for a readability preference. JSON parses with zero dependencies.
- **The schema checker throws on any keyword it does not implement.** That inversion is what stops the document acquiring a constraint nothing checks; `format`, `pattern`, `maxItems` and `nullable` all fail loudly rather than being silently ignored.
- **`additionalProperties` splits on one rule**: open where the shape is owned by an external versioned contract the control plane only recognises a subset of (`EvidenceRecord`, `Workspace`), closed where the seam constructs the body. The open half is NFR-1.1's additive tolerance made structural; the closed half means adding a field to a published response requires editing the document.
- **Routes became an exported data table.** "The document describes all four routes" is only checkable if something other than a reader can enumerate them. `.find()` performs the same two comparisons in the same order as the previous `if` chain, which is why all 8 existing seam tests pass unchanged.
- **Fixtures are inline literals, not imported from `packages/contracts`.** An imported constant would follow a version bump silently and mask the drift the test exists to catch; and the import would declare an Nx edge taking `contracts` fan-in from 2 to 3, flipping `shared` in the component map and permanently retiering every future change to that package.
- **No ADR.** All four substantive decisions were settled by the founder at the Phase ① gate, so there was no open decision to record. `docs/adr/**` maps to the critical `control-plane-policy` component, and the roadmap allocates Sprint 1's one ADR to task 1.2.

## Human Interventions

- **Phase ① gate**: the agent surfaced eight ambiguities, four of them blocking, rather than choosing. The founder settled all four — one 422 with a discriminator, JSON with zero dependencies, route-table refactor approved, both error envelopes published as-is. **Lesson**: a design question that changes the task's SP and tier is a gate decision, not an implementation detail; surfacing it cost one exchange and prevented a ~5 SP rewrite of a shipped seam.

- **Phase ④ cycle 1, Blocker 3**: the agent recommended softening the document over enforcing the fields, and the founder asked why rather than accepting. Answering it properly surfaced that `evaluateGuardrails` truthiness-tests `ai_tool`, so `ai_tool: 42` satisfies CAF-SDLC-010's provenance rule — a fail-open the agent had not found while defending its own recommendation. **Lesson**: when asked to justify a recommendation, re-derive it rather than restating it. The question was worth more than the answer the agent had.

- **Phase ③ fix round**: the founder said "proceed" while the fix round was uncommitted. The agent declined to run `git commit` and re-reviewed against the working tree instead. **Lesson**: the Commit Checkpoint is a control, and an ambiguous "proceed" is not authority to cross it; say so in one line and carry on with what does not need the commit.

- **Phase ④ cycle 3, escalation**: at the three-cycle limit the agent escalated with the recurring pattern named — the document over-stating its own rigour, one level further up each cycle — and three options. The founder authorised one capped fix round. **Lesson**: escalation is more useful as a named pattern plus a recommendation than as a request for guidance.
