## Design Decisions

- **Issuer** `https://token.actions.githubusercontent.com`, compared byte for byte, RS256 only, `iss` and `jwks_uri` reviewed code constants. **Audience** `urn:codeaiforge:sdlc-control-plane:production`, which no GitHub default can equal.
- **Binding on numeric IDs** `(iss, repository_owner_id, repository_id)` held in the reviewed registry, never on names or `sub`: FR-1.2 forbids inferring authority from a name, and `sub` is name-based for older repositories.
- **`workspace-registry/1`** — a required `workload_identity` block, an `admitted_events` allowlist, and optional `required_job_workflow_ref` / `required_job_workflow_sha` pins. Task 2.1 implements it.
- **A six-step validation order** with one status per step (401, 503, 401, 401, 401, 403), so a malformed or forged token gets the same status in every implementation. Step 5 requires every claim `submitted_by` is built from.
- **One identical 403 body** for no registration, an unadmitted event, a pin mismatch and a refused actor; 403, not 404, so registration cannot be probed.
- **Evidence is self-attested and identity-bound** (ADR-0004). The envelope gains `submitted_by`; three response schemas gain a required `evidence_attestation: "self-attested"`. Signing and recomputation were rejected: the engine cannot sign, and recomputation breaks federation.
- **The redacted envelope keeps identifiers and nulls names** — `ref`, `event_name`, `workflow_ref`, `job_workflow_ref` — because a branch name can carry a person's name. Task 2.2's trigger refuses any change to a kept field.
- **The conformance check became the approval control.** `adr-conformance.test.mjs` now refuses an Accepted ADR without a dated "Approved by …" sentence, names the roles for NFR-6 inside that sentence, keeps `stack.md`'s stated statuses equal to each ADR's own, and fails on files in `docs/adr` that no check reads.
