## Task Brief

**Trace**

- **NFR-2.1** — "Before a production endpoint accepts evidence, the system shall authenticate the calling workload and authorize it for the registered workspace."
- **NFR-6.1** — "The system shall retain the approving decision reference and an audit trail for policy changes; it shall not represent automated technical checks as human approval or regulatory certification."

**Acceptance criteria**: AC-1…AC-18 from the Phase ① brief, grouped as trust boundaries (AC-1–4), abuse cases (AC-5–8), mitigations (AC-9–12), residual risks (AC-13–15) and cross-cutting (AC-16–18). The brief's central point: "identifies" is a weak verb, so the four lists must be **joined and total** — every route covered, every abuse case answered, every residual risk owned — which is checkable, where "is this a good abuse case" is not.

## Design Decisions

- **STRIDE per boundary, not per asset**, with all six letters written on every boundary and `n/a` as a recorded judgement. An omitted letter is indistinguishable from one nobody considered. The index is what surfaced TB-7 — the control plane misrepresenting its own assurances has no socket, so a route-driven pass would never find it.
- **Four dense ID spaces referenced rather than repeated** — `TB-n`, `ABU-n`, `MIT-n`, `RR-n` — so the conformance check can hold the relations in both directions.
- **An executable conformance check** (`tools/sdlc-controls/threat-model-conformance.test.mjs`, T1–T11) imports the seam's exported `routes` for totality and reads the roadmap for owner validity. Its header states what it cannot judge: whether a case is well chosen, whether a mitigation mitigates, whether a boundary's `Control` cell is true.
- **The ingress body limit is specified, not shipped** (Phase ① gate): 1 MiB counted on received bytes, `413`, respond then destroy, `openapi.json` + `info.version` bump, owned by 2.1 — plus authenticate before reading the body, read timeouts and a per-principal quota (Phase ⑥).
- **Classification: INTERNAL, covering payload and identifiers** (founder, 2026-09-23). Consequence carried to Gate 2 rather than resolved: ADR-0002's tombstone retains classified identifiers past expiry.
- **Task 1.4 added to the roadmap** (Phase ① gate) to own Gate 2's identity signal, which otherwise would have been produced only by 2.1 — inside the sprint the gate guards. 1.3 models the boundary and hands 1.4 thirteen requirements; the issuer and authorization model are 1.4's.
- **ADR-0002's store is modelled conditionally**, and the check fails CI the day ADR-0002 leaves `Proposed` while TB-5 still says so (Phase ② gate: fail, not warn).
- **No ADR.** The threat model records findings for Gate 2; it decides nothing an ADR would carry.

## Human Interventions

- **Phase ① gate**: four blocking questions → specify the body limit rather than ship it; classify evidence INTERNAL covering identifiers; add task 1.4; put the model in `docs/architecture/` with an executable check. — **Lesson**: a gate signal with no owner inside the sprint that precedes the gate is a missing task, and the cheapest time to add it is the analysis phase that notices.

- **Phase ② gate**: rename `AC-n` to `ABU-n`; keep the check failing CI when ADR-0002 is accepted; write acceptances back into the threat model. — **Lesson**: a condition written as prose rots silently; one the build enforces retires itself.

- **Phase ④ cycle 3, escalation**: the agent named the pattern — a fact written in two places and fixed in one — and the founder authorised one capped round and a pipeline change, here and upstream. The Phase ④ fix step now requires grepping a fix's old value repository-wide before presenting the plan. — **Lesson**: "verify the diff contains the fix" proves a fix landed where it was put, not everywhere the fact lives.

- **Phase ⑤ cycle 1**: QA found four ACs the Phase ② spec had reshaped without saying so. The root cause was the orchestrator: the Phase ② agent was given a summary of the brief, not its ACs, and said so in its own output, which nobody reconciled at the approval gate. The founder chose to fix three in the document and amend three. — **Lesson**: pass acceptance criteria to every phase verbatim; a designer given the substance designs to the substance.

- **Phase ⑥ conditions**: the founder chose to apply every condition now, with a targeted review, over handing the gaps to Gate 2. The review blocked twice, every Blocker again an over-claim or a fact updated in one file only. — **Lesson**: new prose written under a checklist needs the same review as the first draft; the defect class does not change because the author is fixing.

- **Commit plan**: the founder asked for more concise commit bodies. — **Lesson**: a commit body is checked against its diff; bullets that each name one change do that better than paragraphs.

- **Phase ⑦**: the founder fast-forwarded `main` to the branch instead of opening a PR. CI ran on the push and passed, but `sdlc-controls.yml` triggers only on `pull_request`, so the change was never tiered. Computed afterwards, it is **T3** (`tools/sdlc-controls/**` is critical): two approvers and an independent approver required, none given, and `main` has no branch protection. — **Lesson**: this is ABU-6 and RR-1 demonstrated on the task that modelled them; the gate is advisory until branch protection makes it a required check.
