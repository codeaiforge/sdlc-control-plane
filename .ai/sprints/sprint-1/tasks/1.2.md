## Design Decisions

- **An envelope wrapping the record, not an extension of `evidence/0`.** `workspace_id`, `received_at` and `policy_id` are control-plane facts about a submission, not producer claims inside it. This is what keeps the Sprint 1 risk checkpoint green: the store and key were named without reopening the evidence schema.
- **The idempotency key is `JSON.stringify([workspace_id, change_id])`, never a delimiter join.** `['a|b','c'].join('|')` and `['a','b|c'].join('|')` are the same string, so a joined key aliases two distinct pairs and the second workspace's record is answered as a replay of the first and never stored. Pinned by two tests.
- **`workspace_id` is nullable on purpose.** Postgres treats NULLs as distinct under `UNIQUE`, so a null workspace claims no uniqueness with no application code. Until 2.1 authenticates a principal, every submission takes that row of the collision table.
- **Projection happens at the seam, before policy is evaluated.** `JSON.parse` is iterative in V8 while `JSON.stringify` is recursive, so a body the seam can parse may be one the store cannot hold. Evaluating policy first would compute "accepted" for a record about to be lost.
- **No digest of the payload is retained.** A `payload_sha256` was added mid-task so the collision rule would outlive redaction, then removed once Phase ⑥ showed that outliving redaction is precisely what makes an unkeyed digest an offline oracle for the body expiry exists to destroy. A redacted row has no comparand and needs none: it resolves to `duplicate` on the key alone.
- **Append-only is enforced by the database, not by the job.** A dedicated DDL role owns every object; the application role holds `INSERT` and `SELECT` and owns nothing; the one in-place write retention performs is constrained by a `BEFORE UPDATE` trigger that refuses any non-`NULL` write to `evidence` and writes the `evidence_redaction` row itself.
- **Retention's basis is operational, not compliance.** 90 days from `received_at` — one SAFe PI plus margin. No regulation or retention schedule has been cited for this data, and the ADR says so rather than implying one. Evidence data classification is handed to 1.3 undetermined.

## Human Interventions

- **Phase ④ cycle 2 gate**: the agent surfaced two findings as decisions rather than choosing — whether to correct the prose or the code for the projection band, and whether `policy_id` belonged in the envelope now or in 2.2. The founder took "say what is actually true" and "add it now". **Lesson**: a finding that can be closed either by changing a document or by changing behaviour is a gate decision, because the two answers leave different systems behind.

- **Phase ④ cycle 3, escalation**: at the three-cycle limit the agent escalated with the pattern named — documents over-stating their own rigour, one level further up each cycle — and the founder authorised one capped fix round. **Lesson**: the escalation was worth more than a fourth silent cycle, because the named pattern is what predicted where the next defect would be.

- **Commit plan, `run-task.prompt.md`**: the founder said _"the file is not in the changes."_ Correct — the agent had recommended a rewording in one turn and asserted it as done in the next, having never applied it. Its own verification pass had covered only two of the three files in the plan. **Lesson**: verify every file the plan names, not the ones most recently touched; `git status` alone would have caught this in one second.

- **Redirection to a tool**: asked whether the last commit should go back upstream, the agent answered per-file. The founder replied _"we need an automated mechanism for the patches."_ **Lesson**: a second instance of a manual step is a signal to build the mechanism, not to repeat the step more carefully. The resulting drift report immediately found 11 missing governance files and 12 divergent ones that nobody had noticed.

- **Phase ⑥, TS-2**: the agent presented three shapes for the digest defect it had itself introduced and recommended dropping the digest; the founder took that. **Lesson**: a fix that creates a second defect is a sign the first fix was aimed at the wrong level — dropping the column made both problems disappear, where keying it would have added a secret to a system that owns none.

- **Sequencing**: the founder deferred the `.ai/workflows` sync until after 1.2 closes, so that the task would not be reviewed under one set of pipeline rules and verified under another. **Lesson**: changing the governance layer mid-task invalidates the phases already run against it.
