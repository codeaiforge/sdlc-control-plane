## Design Decisions

- **D-1 One exchange per request** — `main.mjs`: `send()` takes `{ outcome, caller }` and records before writing; a module-private `WeakMap` holds the exchange, so call sites and handler signatures stay as they were. A second `send()` for one request is a late fault, never a second event (D-e); a route that returns without answering is answered 503 `handler-fault` (S-1).
- **D-2 Closed vocabulary** — `telemetry.mjs`: 33 refusal reasons, 39 `(status, outcome)` pairs; event kinds `startup`, `refusal`, `accepted`, `served`, `readiness`, `telemetry`, each a closed key set built from seam-owned values. Principal is the four numeric ids and `workspace_id`; no request field, URL, header, token or driver message.
- **D-3 Totality held by test** — `telemetry.test.mjs` derives every pair from source (call sites, store outcomes, guardrail dispositions) and drives each one; a throwing sink or record changes no response and is a `telemetry_faults` count.
- **D-4 Counts** — per process, since start, by route, status and outcome; `slow` at `SLOW_RESPONSE_MS = 1000`; `late_faults`, `connections_without_request` (Q-13); one snapshot every 60 s on an unref'd timer and one at SIGTERM/SIGINT, after which the signal is re-raised.
- **D-5 Readiness** — `readiness.mjs`: single-flight, a settled answer reused for 2000 ms, no probe waits over 2000 ms (`check-timeout`), closed reasons, fails closed (`not-configured`). The check lives beside the store (`postgres-store.mjs`), runs through `run()` (cancel at 5 s), and does not re-run the startup role check (D-4 of the spec).
- **D-6 ADR-0005** — the probe-route class (`GET /health`, `GET /ready`): no credential, a status-only body, no header read but framing; ADR-0003's predicate applies outside it. ADR-0003 not edited.
- **D-7 Startup line** — names `policy_id`, `decision_id`, schema version and registered-workspace count; the fixture's `{"port": n}` stdout contract unchanged.
- **D-8 `retention-check`** — `pnpm nx run evidence-store:retention-check`, as `evidence_audit` only (refuses superusers, elevated attributes, memberships), one `repeatable read read only` transaction, `statement_timestamp()`, 30 s statement timeout; window imported from `expire.mjs`, grace `48 hours`. Finds `guard-absent`, `guard-replaced`, `guard-disabled`, `overdue-payload`, `unaudited-redaction`, `early-redaction`, `future-redaction`, `future-receipt`; prints nine fixed lines of counts and hours and the ceiling line every run; exit 0 none found, 1 found, 2 usage, 3 refused or failed (a crash cannot read as 1, S-2).
- **D-9 Guard pinned as the migrations make it** — trigger type, WHEN, UPDATE OF, arguments, function body (from the bundled migration), function `search_path`, column types, positions and collation, the pairing CHECK and the redaction FK; anything else reads `replaced`, exit 1. Some function attributes (`proisstrict`, `proparallel`, `procost`, `proacl`) are deliberately unpinned, measured harmless.
- **D-10 Connection-phase errors** — any non-refusal error of the first statement reports `database-unreachable` (D-a), since TLS and connect-timeout codes fall outside the spec's SQLSTATE/errno table.
- **D-11 Mislabel fixed** — a body read that throws is `400 body-read-failed`, no longer `body-not-json` (spec D-2).
- Implementation deviations D-a…D-m are recorded in `2.3-implementation-notes.md` and judged in review cycle 1.
