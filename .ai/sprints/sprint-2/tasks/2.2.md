## Design Decisions

- **D-1** — new leaf `packages/evidence-store` (`scope:persistence`, `criticality:critical`, fan-in 1); the port and its conformance suite moved there.
- **D-2** — postgres.js 3.4.9, no dependencies of its own; `sql.unsafe` only in the migration runner, on bundled files, enforced by a structural test.
- **D-3…D-7** — `evidence` schema, four fixed roles (owner, app, retention, audit) with column-level grants; the app role's `INSERT` omits `redacted_at` and `received_at` (the database clock stamps it); a `SECURITY DEFINER` trigger with pinned `search_path` admits only a well-formed redaction and writes its audit row itself; no non-superuser can delete an envelope.
- **D-8** — append is `INSERT … ON CONFLICT DO NOTHING` then a lookup scoped to the workspace (40 concurrent appends of one key: 1 row).
- **D-9** — 5 s per statement; a `TypeError` from the store is 400, anything else 503; the request handler's promise never rejects (closes 2.1's SEC-6).
- **D-15, D-16** — `createApp` has no default store; startup refuses on unsafe config, unverified TLS to a non-loopback host, an unsafe role (elevated attribute, membership of any role, an ownership, a write grant on the log or its redaction table, `INSERT` on `received_at`/`redacted_at`) or a schema mismatch.
- **Measured driver behaviour** — jsonb bound as `::text::jsonb` (a direct bind stores a JSON string); every driver option passed explicitly (postgres.js falls back to `PG*` env vars and ignores `PGSSLMODE`); driver errors never logged (they carry row data and parameters).
- **Deviations from ADR-0002's text** (stricter, ADR not edited): the trigger is `SECURITY DEFINER` and the retention role holds no `INSERT` on `evidence_redaction`; the owner gives up `DELETE`/`TRUNCATE`; `policy_id` kept and immutable after redaction; `received_at` is the database's clock.

## Human Interventions

- **Phase ① gate**: the agent counted 31 handoffs (~13 SP) under an 8 SP row and recommended a split → the founder split off 2.5 (retention job). — **Lesson**: as in 2.1, the ADRs and threat model are the scope; count them before accepting the row.
- **Phase ③ commit plan, "do we need so many commits?"**: the agent read the per-file rule as one file per commit and produced 24 commits with two index patches → the founder clarified the rule: **a file may belong to at most one commit**, not one commit per file. — **Lesson**: the rule forbids intermediate states, which removes the need for `git apply --cached` patches; design commit order around files landing once, final.
- **Commit-plan replay**: the agent's (and Phase ③ sub-agent's) replays ran Nx against the real repo, because the shell exports `NX_WORKSPACE_ROOT_PATH` → found when C04 ran tests that did not exist yet in the copy. — **Lesson**: a replay in a scratch copy must set `NX_WORKSPACE_ROOT_PATH` to the copy; a gate that passes too easily is evidence of measuring the wrong tree.
- **Option B → A**: the agent recommended adding the new package first and deleting the old files later (B); replay showed the fan-in table makes the package land only with its first importer → the founder chose A (one large coupled commit). — **Lesson**: say a recommendation's risk out loud before the founder chooses; here the flagged risk was the deciding fact.
- **C04 staging**: `git add` on deleted paths already removed from the index failed ("pathspec did not match") → `git rm --cached --ignore-unmatch` for deletions. — **Lesson**: a staging command must work whatever the index already holds.
- **C04 content**: `admission.mjs` landed in C04 by mistake → the founder asked for it out; the agent gave a `reset --soft` + `commit -C` sequence (branch unpushed). — **Lesson**: verify the landed commits' file lists, not just their messages.
- **Phase ④ cycle 2 → merge**: `main` was fast-forwarded and pushed before cycle 2 approved. — **Lesson**: as in 2.1, for the solo founder later phases verify `main`; fix rounds land there.
- **Phase ⑤ / ⑥ findings**: the founder took every recommended docs fix and the override. — **Lesson**: a new upstream advisory can turn a green task red between phases; re-run the audit at each phase gate.
- **README restructure**: the founder asked whether the README should match the other open-source repos (e.g. `git-native-sdlc-controls`) → scheduled as additional work after 2.2 (option 1), not inside the task. — **Lesson**: public-facing positioning is the founder's decision and stays out of a task's review cycles.
