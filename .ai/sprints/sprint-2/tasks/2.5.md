## Design Decisions

- **D-1 Window in the database** — `0002-retention-window.sql` re-creates 2.2's trigger function (`CREATE OR REPLACE`, so owner, ACL, `SECURITY DEFINER` and the pinned `search_path` are kept) with every 2.2 check unchanged plus one: a redaction of an envelope whose `received_at >= statement_timestamp() - interval '2160 hours'` is refused (`P0001`), for every role, the owner and a superuser included.
- **D-2 The job** — `packages/evidence-store/src/expire.mjs`, `pnpm nx run evidence-store:expire`: refuses before any `BEGIN` as `config-invalid`, a connection code, `role-unsafe` (superuser, member of any role, `CREATEROLE`/`CREATEDB`/`REPLICATION`/`BYPASSRLS` — the service's own check), `not-retention`, or `schema-mismatch`; then batches of 1000 ids, each one transaction with a 30 s statement timeout, `FOR UPDATE SKIP LOCKED`, until a batch redacts nothing. Prints `expire done: redacted N` or `expire refused: <code>`; exit 0, 1 or 2 when run directly (1 for a usage error through Nx, as `migrate`).
- **D-3 One window, two copies** — the literal `'2160 hours'` lives in the job and the trigger; a unit test pins both, and the ±1 min boundary test catches drift either way.
- **D-4 Live-row index** (review S-1) — `evidence_envelope_live_id ON (id) WHERE redacted_at IS NULL`: with 2 M tombstones a batch fell from 336 ms (primary-key scan filtering every tombstone) to 81 ms; tombstones are kept forever, so without it every run would eventually hit its timeout.
- **D-5 Back-dating is test-only** — `pg-harness.mjs` `age()` sets `received_at` as the superuser with `session_replication_role = replica`, inside one transaction; only test files import the harness.
- **D-6 No scheduler, no ADR** — scheduling is the deployment's (the stack's deploy target is still Not selected); behaviour stricter than ADR-0002's text is recorded here, as 2.2 did.
- **Erasure consequence of Q-2 B** — no role can redact a payload younger than 90 days, so an erasure or a takedown request needs a reviewed migration. Stated in the 0002 header, ABU-12 and the stack's Access control row (SEC-3).
