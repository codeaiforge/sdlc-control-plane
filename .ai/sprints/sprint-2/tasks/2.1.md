## Design Decisions

- **D-1, D-2** — RS256 verified by hand over `node:crypto` in a new leaf package `packages/workload-identity` (`scope:identity`, `criticality:critical`); Phase ⑥ confirmed keeping it over `jose`.
- **D-3, D-4** — key fetch and clock injected; test keys and tokens generated in-test; claim shapes in one `MEASURED` block per test file.
- **D-5** — two GitHub-only measuring workflows that print the decoded header and payload, never the token.
- **D-6** — 1 MiB counted body cap → 413; 10 s / 30 s timeouts checked every 1 s; 60 submissions / 60 s per principal per process → 429.
- **D-7** — one closed-schema JSON refusal line on stderr per refusal; principal only after step 5.
- **D-8** — policy reason reworded to `required control not claimed: <id>`.
- **Connection handling** (Phase ④) — one `send()` closes on every refusal and on any response sent while the body is unread, including Node's own `Expect` paths; no keep-alive is promised.
- Contract `openapi.json` 0.1.0 → 0.2.0 once: 401/403/429/503, 413, `evidence_attestation`, `Workspace` at `workspace-registry/1`.

## Human Interventions

- **Phase ① gate**: the agent found ~21 criteria under an 8 SP row and recommended a split → the founder split off 2.4. — **Lesson**: a task row is not its scope; ADRs and the threat model hand work to a task by name, and only counting them shows the real size.
- **Phase ① gate, Q-2**: the founder offered local GitHub Actions for the measurement → the agent explained `act` cannot mint a GitHub-signed token, so the mirror was used. — **Lesson**: a measurement of an issuer must come from that issuer; a simulator measures itself.
- **Phase ③ → ④**: the brief and spec were moved to the desktop trash mid-task, cause unknown → the founder asked whether work files should be kept at all; kept untracked, then `.ai/sprints/*/work/` git-ignored. — **Lesson**: phase inputs need a home that survives both a reboot and a cleanup, and that is never committed.
- **Commit plans**: the founder asked for the plan as files, subject and body bullets per commit rather than a table. — **Lesson**: a commit plan is something to execute, not a summary; give it in the shape it will be typed.
- **Phase ④ cycle 1, B-1**: code or document → the founder chose the code, generalised to every unread-body response. — **Lesson**: generalising a fix to its root mechanism closed a Suggestion (S-1) with the Blocker.
- **Phase ④ cycles 1–3, Suggestions**: the founder took only what the agent showed to be inside the ACs (S-2, S-3, S-7, N-7) and declined the rest. — **Lesson**: declined findings are still owed a line in the record; they are open, not gone.
- **Phase ④ escalation**: the pattern named — each round's sentence about what _keeps_ a connection missed the next case Node decides itself (404 → 417 → 100-continue) → the founder chose a one-way claim. — **Lesson**: do not publish promises about behaviour the code does not control; state what the code guarantees, and stop.
- **Commit `be837ab`**: the agent's own bullet said a comment "states exactly" which responses keep the connection, and it did not → corrected by a follow-up commit, not a rewrite. — **Lesson**: "exactly" in a commit body is a claim the next review will test.
- **Phase ⑤ / ⑥ findings**: the founder took F-1 and SEC-1 only. — **Lesson**: a Conditional Pass's condition can be one line (`pnpm.overrides`); offer the cheapest fix first.
- **AC-20, the push**: the agent told the founder to push `measure/oidc-token`; the founder pushed `main` (fast-forwarded to the task) and the workflow, triggered only by that branch, did not run → started by `workflow_dispatch`. — **Lesson**: when a workflow file reaches the default branch, a manual run is simpler than a trigger branch; give that path first.
- **Phase ⑦ → ⑧ ordering**: the task reached `main` and both remotes before Phase ⑧. — **Lesson**: for a solo founder, Phase ⑧ verifies `main`, not a branch; the measurement's follow-up commits land there.
- **AC-20 commits**: the founder asked why five identical edits were five commits → the agent cited the per-file rule and offered the single-commit form. — **Lesson**: the per-file rule serves checkability; for one mechanical edit across files it is the founder's call, case by case.
