## Design Decisions

- `createRequestHandler({ registry, policy, evidence })` is exported separately from `createApp()`. The handler is a pure function of injected state, so every route is exercisable without a listening socket — which is the acceptance criterion, and also what makes the seam testable in CI without port allocation.
- Four routes on `node:http` with no framework. The seam proves the contract flow; a router is a production concern and would be a dependency added ahead of need.
- Status codes carry the disposition: 202 with the decision when accepted, 422 with reasons when guardrails reject, 400 when the body is not JSON, 404 otherwise.
- Rejected evidence returns before `evidence.push`, so it cannot reach the indicator summary. That is FR-2.2's third acceptance criterion enforced by control flow rather than by a filter at read time.
- Accepted records are frozen on push.
- Config is read at module load from `config/control-plane/`, which couples the deployable to reviewed policy on disk and is why the config ships in the same commit.

### Finding — three of four routes have no test — RESOLVED 2026-09-21

The criterion asks that the paths be _testable_, and they are: the injectable handler makes
all four reachable without a socket. Only `/health` is actually tested. `/v1/workspaces`,
`/v1/indicators` and `POST /v1/evidence` — including the 202 / 422 / 400 branches that carry
FR-2.2 — have no coverage at this seam, and FR-2.2 is 0.4's only trace.

This was not a failure of the criterion as written — roadmap task 1.1 schedules the contract
tests — but the gap left FR-2.2 unverified at the seam that traces to it.

**Resolution (2026-09-21)**: `packages/control-plane-api/src/main.test.mjs` now covers all
four routes and every branch: workspace listing with owners and value stream, 202 on
accepted evidence, 422 with actionable reasons on an unmet control, 400 on an unparseable
body, 404 on an unknown path, and both indicator paths — including the assertion that
rejected evidence never reaches the summary, which is FR-2.2's third acceptance criterion.
Test count at this seam went from 1 to 8.

Task 1.1 still owns the OpenAPI document and the contract tests written against it; this
remediation covers the seam's behaviour, not its published contract.
