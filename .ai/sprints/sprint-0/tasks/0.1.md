## Task Brief

**Trace**: NFR-1.1 — the system shall reject an unknown major contract version and tolerate unrecognised additive fields on a supported version.

**Acceptance criteria** (from "Done when"): five Nx projects are discoverable, and the component map derives component paths and fan-in from the graph.

**Constraints**: the component map feeds `sdlc-controls tier`, which computes blast radius per pull request. A wrong path or fan-in silently mistiers a change.

## Design Decisions

- Five libraries under `packages/`, each with its own `project.json`, `scope:*` tag and `criticality:*` tag. The Nx graph — not a checked-in list — is the architecture of record.
- `generate-component-map.mjs` reads project roots from graph nodes and reads `criticality:` off the tags, so a new project appears in the map without editing the generator.
- Five hand-written components cover paths Nx does not own: the gate itself, control-plane policy, CI, workspace config, docs.
- `shared: true` at fan-in >= 3; `breadth_threshold: 4` and `unmatched_path_tier: high` are the map's declared defaults.
- The generator throws on an unknown criticality tag or an unmappable root project rather than emitting a map the tiering binary would misread.

### Finding — graph edges are hand-declared, not derived — RESOLVED 2026-09-21

Every edge in the Nx graph is an `implicitDependencies` entry in `project.json`. Nx resolves
project edges from package-name imports; these packages import each other by deep relative
path (`../../contracts/src/schema.mjs`), which Nx does not resolve, so the edges were
declared by hand.

One declared edge is already wrong: `indicators -> contracts` exists in
`packages/indicators/project.json`, but `summarize.mjs` and `summarize.test.mjs` import
nothing from `contracts`. The same applies to `control-plane-api -> contracts`.

This inflates the fan-in of `contracts` from 2 real importers to 4 declared ones, which
crosses the `shared` threshold of 3 and marks it `shared: true`. The criterion "fan-in from
the graph" is met — the generator does read the graph — but the graph is a hand-maintained
claim about imports, so the blast-radius signal degrades silently as the code drifts.

**Resolution (2026-09-21)**: the two false edges were removed from
`packages/indicators/project.json` and `packages/control-plane-api/project.json`, and
`tools/sdlc-controls/graph-fidelity.test.mjs` now fails when a declared dependency has no
matching import, or an import has no declared edge. `contracts` fan-in now reads 2 and the
map emits `shared: false` for it, which is accurate. The check runs in both CI workflows
through the existing `tools/sdlc-controls/*.test.mjs` glob.

A second problem surfaced while wiring that check: `packages/control-plane-contracts/`
existed as an empty directory pair with no `project.json`, invisible to git because git does
not track empty directories, and invisible to the graph. It was leftover scaffolding from an
earlier name for `contracts`. Removed, and a second assertion now fails if any directory
under `packages/` has no `project.json`.
